# ADR-004: Data and Scientific Provenance

- **Status:** Accepted
- **Date:** 2026-09-22
- **Decision Type:** Data Architecture
- **Scope:** Botanica Indica platform and ecosystem

## Context

Botanica Indica will combine information from multiple sources and workflows.

Potential information sources include:

- Taxonomic databases
- Botanical floras
- Biodiversity databases
- Scientific literature
- Observation platforms
- Geographic datasets
- Institutional datasets
- User contributions
- Photographs and other media
- AI/ML identification systems
- Expert reviews
- Derived datasets

These sources may differ in:

- Authority
- Scope
- Taxonomic treatment
- Geographic coverage
- Date
- Version
- Licensing
- Accuracy
- Completeness
- Scientific interpretation

A botanical record without information about its origin can become difficult to verify, correct, reproduce, or legally reuse.

The ecosystem therefore requires provenance to be treated as a fundamental property of scientific and botanical information.

## Decision

Botanica Indica will implement **provenance-aware data architecture**.

Important scientific and botanical information should retain sufficient provenance to identify:

- Where the information came from
- When it was obtained
- Which source or dataset version was used
- How it was transformed
- Whether it was generated by a person, external source, algorithm, or AI/ML system
- Whether it has been reviewed or validated
- What licensing or usage restrictions apply where relevant

Provenance should be retained throughout the lifecycle of the information.

## Data Categories

The system will distinguish between different categories of information.

### 1. Original Project Data

Information created directly by Botanica Indica.

Examples include:

- Project-generated taxonomic relationships
- Platform-generated metadata
- Internal validation records
- Platform-generated analytical results

### 2. External Source Data

Information obtained from external sources.

Examples include:

- Taxonomic records
- Published scientific information
- External biodiversity observations
- External geographic datasets
- External photographs

External information must retain appropriate source attribution and licensing information.

### 3. User-Contributed Data

Information submitted by users.

Examples include:

- Plant observations
- Photographs
- Identification suggestions
- Corrections
- Comments
- Field notes

The system should retain the contributor and relevant submission metadata according to applicable privacy and platform policies.

### 4. AI/ML-Generated Information

Information generated by automated models.

Examples include:

- Candidate species
- Classification results
- Confidence values
- Feature or embedding outputs
- Automated recommendations

AI-generated information must remain distinguishable from human or scientifically validated information.

### 5. Expert-Reviewed Information

Information that has undergone review by an appropriately authorized expert or scientific reviewer.

The system should retain:

- Reviewer identity or authorized reviewer reference
- Review date
- Review outcome
- Relevant evidence
- Review history

### 6. Derived Data

Information produced by processing one or more source datasets.

Examples include:

- Reconciled taxonomic records
- Aggregated observations
- Distribution maps
- Search indexes
- Statistical datasets
- Model training datasets
- Analytical outputs

Derived data must retain sufficient references to the source information and transformation process to support reproducibility where practical.

Source Identity

External sources should have stable internal source records.

A source record may contain:

Source name
Organization or publisher
Source URL or identifier
Dataset identifier
Version
License
Attribution requirements
Access date
Update frequency
Source type
Import status

The system should avoid storing external information without retaining enough information to identify its origin.

Source Versions

Where an external source provides versions, Botanica Indica should retain the relevant version information.

For example:

Source: Example Taxonomic Database
Version: 2026.09
Retrieved: 2026-09-22

When a source changes, the system should be capable of determining which version contributed to a record where practical.

This is especially important for:

Taxonomic changes
Species names
Synonym relationships
Geographic distributions
External observations
Scientific datasets
Transformation Provenance

When external data is transformed before entering the platform, the transformation should be documented.

Examples include:

External CSV
    ↓
Parsing
    ↓
Normalization
    ↓
Taxonomic Matching
    ↓
Deduplication
    ↓
Validation
    ↓
Botanica Indica Record

Where practical, the system should retain:

Original source
Transformation process
Transformation version
Processing date
Validation outcome
Taxonomic Provenance

Taxonomic information requires special provenance handling because different authoritative sources may use different classifications.

The system must be capable of representing:

Accepted names
Synonyms
Basionyms where relevant
Taxonomic authorities
Alternative classifications
Historical names
Source-specific treatments
Taxonomic versions

The existence of multiple taxonomic treatments should not automatically be interpreted as an error.

The platform should preserve source context rather than silently overwriting differences.

Identification Provenance

Plant identification results should retain information about how the result was produced.

Potential provenance fields include:

Identification Method
Model
Model Version
Input Observation
Input Image
Candidate Generation Time
Taxonomic Version
Confidence
Supporting Evidence
Human Confirmation
Expert Review

For example:

Image
  ↓
Model A v3.2
  ↓
Candidate: Species X
  ↓
Taxonomic Resolution
  ↓
User Confirmation
  ↓
Expert Review

Each stage should remain distinguishable.

Evidence Provenance

Scientific claims should be traceable to their supporting evidence where practical.

Evidence records may reference:

Scientific publications
Books
Floras
Institutional databases
Taxonomic databases
Observation records
Expert assessments
Other documented sources

The platform should distinguish between evidence and conclusions derived from evidence.

Validation Status

The system should represent the status of information explicitly.

Possible states include:

Submitted
AI Identified
User Confirmed
Expert Reviewed
Scientifically Verified

These states are not necessarily mutually exclusive and the exact validation model may evolve.

The system should preserve the history of significant validation changes rather than only storing the latest state.

Uncertainty

The platform must support uncertainty.

Information should not be presented as scientifically certain merely because it exists in the database.

Examples include:

AI identification with low confidence
Conflicting taxonomic sources
Incomplete geographic information
Uncertain observation location
Ambiguous species identification
Conflicting evidence
Historical records with limited supporting information

Where uncertainty is scientifically meaningful, it should be represented explicitly.

Conflicting Sources

Different sources may disagree.

Examples include:

Different accepted species names
Different synonym relationships
Different geographic distributions
Different identification results
Different scientific interpretations

The system should preserve relevant source-specific information rather than silently selecting one interpretation without documenting the basis.

Where reconciliation is performed, the reconciliation itself should be represented as a derived decision or relationship with appropriate provenance.

Licensing Provenance

Public availability does not automatically imply unrestricted reuse.

Every external dataset or media source incorporated into the ecosystem must be evaluated for applicable:

Copyright
License
Attribution requirements
Usage restrictions
Commercial-use restrictions
Share-alike requirements
Database rights
Terms of service
Other applicable conditions

The platform must preserve licensing information where practical.

Third-party data must not be relicensed as Botanica Indica's original data merely because it has been imported or transformed.

Photograph and Media Provenance

Images and other media require their own provenance.

Where applicable, the system should retain:

Creator
Source
License
Attribution
Uploading user
Original source identifier
Usage restrictions
Modification history

Media should not be assumed to be freely reusable solely because it is publicly visible online.

Privacy and Sensitive Data

Provenance must not override privacy or conservation protections.

Some information may require restricted access.

Examples include:

Sensitive species locations
Private observations
Personally identifiable information
Restricted institutional datasets
Protected research information

The system should preserve provenance while applying appropriate access controls.

Reproducibility

Where practical, important derived scientific outputs should be reproducible.

A reproducible workflow should identify:

Input Data
    +
Source Versions
    +
Transformation Code
    +
Transformation Version
    +
Configuration
    +
Execution Date
    =
Derived Output

Exact reproducibility may not always be possible, particularly where external services or continuously changing models are involved.

In such cases, the system should preserve as much execution and source metadata as reasonably possible.

Audit History

Important scientific and data changes should have an audit history where appropriate.

Examples include:

Taxonomic changes
Identification corrections
Expert reviews
Data imports
Provenance changes
Source updates
Validation status changes

Audit information should help determine:

What changed
When it changed
Why it changed where documented
Who or what performed the change
Which source or evidence supported the change
AI and Scientific Authority

AI-generated information must not automatically be treated as scientific authority.

The architecture must allow a distinction between:

AI Prediction
      ↓
Human / Expert Review
      ↓
Scientific Validation

An AI prediction may be useful evidence or a candidate identification without being treated as a scientifically verified conclusion.

The platform should support cases where the AI system is unable to produce a reliable identification.

Data Lineage

The system should support lineage relationships between records where practical.

For example:

External Source
      ↓
Imported Record
      ↓
Normalized Record
      ↓
Reconciled Record
      ↓
Derived Dataset
      ↓
AI Training Dataset
      ↓
AI Model
      ↓
Identification Result

This lineage should help users and maintainers understand how information moved through the ecosystem.

Consequences
Positive consequences

This decision provides:

Greater scientific transparency
Better traceability
Improved reproducibility
Better taxonomic accountability
Easier correction of erroneous information
Clearer distinction between evidence and inference
Better licensing compliance
Improved ability to compare sources
Greater trust in scientific workflows
Better support for future research
Negative consequences

This approach requires:

Additional metadata
More complex data models
Provenance management
Source and license tracking
More storage
Additional ingestion work
More deliberate scientific governance

The project accepts this additional complexity because provenance is fundamental to a scientific botanical intelligence platform.

Consequences for Development

Provenance should be considered when designing new data models and ingestion pipelines rather than added as an afterthought.

New components that introduce scientific or externally sourced information should answer:

Where did this information come from?
Which version of the source was used?
When was it obtained?
Was it transformed?
What transformation was applied?
What license governs the source?
Has the information been reviewed?
What uncertainty remains?
Can the information be traced back to its source?
